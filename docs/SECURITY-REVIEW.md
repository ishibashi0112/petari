# petari セキュリティ説明資料(情報システム部門向け)

社内で承認済みのチャット AI(Microsoft 365 Copilot Chat など)を使って開発するための
コマンドラインツール petari の導入審査用の資料です。
どのデータがどこへ出るか、ツールが何をして何をしないかを、コードで確かめられる形でまとめます。

- 対象: petari 0.15.0(2026-11-01 時点)
- ソース: <https://github.com/ishibashi0112/petari>
- ライセンス: MIT
- 以前の slnmix(パックを作る側)と petari(変更を当てる側)は、0.15.0 で petari の 1 パッケージにまとめました。
  slnmix のパッケージは、引数をそのまま petari に渡すだけの互換パッケージとして残します(依存は petari だけ。§8)

## 1. 要約

| 観点 | 回答 |
|---|---|
| 外部への通信 | 実行時はしない。通信するのはインストール時の npm レジストリだけ(§3) |
| AI に渡るデータ | 利用者が自分でチャット画面に貼り付け・添付したものだけ。送り先は社内で承認済みのチャット AI で、ツールが新しい送り先を増やすことはない(§2, §4) |
| AI の権限 | ない。AI は PC 上でコマンドを実行できず、ファイルにも直接触れない |
| 書き込む範囲 | プロジェクトのフォルダの中だけ。パックの出力ファイル・初期設定と、AI の変更を書く。外へのパス・シンボリックリンク経由の書き込みは拒否する(§5, §7) |
| 依存パッケージ | 実行時依存ゼロ(Node.js の標準機能だけで動く)。他者のコードの同梱もない(§8) |
| 起動する外部コマンド | クリップボード・レジストリ参照・git などの OS コマンドと、利用者が `petari build` を実行したときの MSBuild だけ。いずれもシェルを通さない(§6) |

## 2. データの流れ

1. 利用者が開発 PC で `npx petari pack` を実行する。petari はソースを読んで 1 つのテキスト
   (パック)にまとめ、プロジェクト直下のファイルとクリップボードに出す
2. 利用者がブラウザでチャット AI を開き、パックを本文に貼る(大きいときは添付する)。
   **PC の外へデータが出るのはこの操作だけ**
3. チャット AI が、変更内容を changes.md というテキスト(どのファイルのどこをどう変えるか)で返す
4. 利用者が changes.md をダウンロードし、`npx petari` を実行する(または常駐中の
   `petari watch` が拾う)。petari は形式とパスを検証してから、プロジェクトのファイルを書き換える
5. 利用者が git diff で変更を確認してから、ビルド・テストを実行する

petari は通信しません(§3)。AI が PC 上で何かを実行する経路もありません。

## 3. 外部への通信

- ネットワークを扱うモジュール(http / https / net / tls / dgram / dns)と fetch を一切使っていません。
  ポートの待ち受けもありません。差分表示(`petari show`)で VS Code が無いときは、JS を含まない
  HTML ファイルを書き出して既定のブラウザで開くだけです(0.12.0 まであった、127.0.0.1 の一時サーバーと
  同梱エディタによるブラウザ編集は 0.13.0 で廃止)
- **インストール時**: `npx petari` は初回に npm レジストリ(registry.npmjs.org)からパッケージを取得します。
  社内レジストリ(ミラー)経由にする、または版数を固定して導入する方法は §8 を参照してください

確かめ方(ソースを取得して実行):

```sh
grep -rnE "from ['\"](node:)?(https?|net|tls|dgram|dns)['\"]|require\(['\"](https?|net|tls|dgram|dns)['\"]\)|fetch\(" petari/src
```

該当なしです。

## 4. AI に渡るデータと、その制御

### 4.1 パックに入るもの

パックに入れるファイルは、プロジェクトが宣言したものから決めます。ディレクトリを推測で丸ごと
走査することはしません。

- **VB.NET(.sln / .vbproj)**: `.sln` / `.vbproj`(Visual Studio のプロジェクト定義)を解析し、
  **ビルド対象として登録されているソース**を入れます。新しい形式(SDK スタイル)の `.vbproj` では、
  既定でビルド対象になるプロジェクトフォルダ内の `*.vb` も入ります。設定ファイル(`petari.config.json`。
  旧名の `slnmix.config.json` も読む)の `extraRoots` に書いたディレクトリも入ります
- **それ以外の言語**(設定ファイルの `kind: "generic"`): `extraRoots` に書いたディレクトリか、書いていなければ
  **git が管理しているファイル**(`git ls-files --cached --others --exclude-standard` の一覧。コミット済みのものと、
  `.gitignore` に一致しない未コミットのもの)を入れます(0.15.0 から)
- どちらでも入るもの: `docs/` の設計書・仕様書・引継ぎ書、作業手順と出力規約の文、
  `docs/db/schema.md` があればその内容(別ツール ashiato が書き出すテスト用 DB のテーブル定義。
  列・型・主キー・コメントだけで、行の値は含まない。§4.5)
- 入らないもの: `.gitignore` / `.repomixignore` に一致するファイル、`node_modules` / `dist` / `build` /
  `.env*` などの既定の除外、バイナリ、画面デザイナーの自動生成ファイル(コントロール構成の要約だけを入れる)。
  git の一覧から集めるときは、ロックファイル(`package-lock.json` など)と 256KB を超えるファイルも除きます。
  除外したファイルは理由付きでパック内に一覧されます。`.gitignore` / `.repomixignore` に
  一致するファイルは、`petari build` のエラーの文面にも抜粋を載せません
- 注意: `.vbproj` がプロジェクトの外(別ドライブなど)のファイルを参照している場合は、
  そのファイルも入ります(ビルドに使われるため)。git の一覧から集めるときは、コミットしていない
  ファイルでも `.gitignore` に書いていなければ入ります。入れたくないファイルは `.gitignore` か
  `.repomixignore` に書いてください

### 4.2 認証情報の自動マスク

パスワード・ユーザー ID・API キー / トークン・秘密鍵らしき文字列リテラル(連結で続くリテラルも)と、
接続文字列の `Password=` などの値を、既定で `[MASKED]` に置き換えます。設定ファイルでは、
`.NET` の appSettings(`<add key="DbPassword" value="..." />`)・My.Settings(`<setting name="DbPassword">` の
`<value>`)・JSON などの `"password": "..."`・`DB_PASSWORD=...` の値も伏せます。
コードの `dbPassword = "..."`(型の注釈つきの `password: string = "..."` / `password:str="..."`・C# の自動プロパティの初期化子・
Go の `:=` も)・C# の `@"..."` / `$"..."`・Python の `u"..."` / `f"..."` / `r'...'`・文字列の中の `Password=\"...\"`・リテラルをまたいで続く
接続文字列の値・リソース(.resx)の `<data name="DbPassword">` の値・VB のコメントアウトした宣言(`' Dim strPwd As String = "..."`)・
VB の型文字つきの宣言(`Dim strPwd$ = "..."`)・URL の利用者情報のパスワード(`postgres://user:...@host`。`&amp;` / `&#x40;` などの文字参照・
`${DB_PASSWORD:-既定値}` の既定値も)・
バッチファイルの `set DB_PASSWORD=...`(`&` でつないだもの・`if` / `@` の後のもの・`set "..."` / `set \"...\"` のように引用符で囲んだもの・
MSBuild の `Exec` やビルド後イベントに書いたものも。SQL の `UPDATE 表名 SET ...`(`THEN` / `DO` の後の `UPDATE SET` も)と、値がバインド変数(`:名前` / `@名前` / `?` など)で、名前がキーと同じ(`SET LOGIN_PASSWORD=:LOGIN_PASSWORD`)か、後ろに `,` / `WHERE` が続くか、同じ行か前の行に `UPDATE` があるものは除きます)・
パスワードを引数で渡すコマンド(`sqlcmd` / `osql` / `bcp` の `-U` と一緒に渡す `-P`(コマンド名のない引数の文字列の `-U ユーザー -P ...` も)、
`mysql` の `-p...` / `--password=`、`mysqladmin` の `password`、`net use` のパスワード(`/user:` の後に書いたものも)、`schtasks` の `/RP` / `/P`。
行の継続(`^` / `\`)・MSBuild の `&quot;` で囲んだもの・VB の文字列の中のものも。`%SA_PASSWORD%` / `$Password` などの変数の参照・差し込み・
入力を求める `*`・リダイレクト・前後に空白のある `&` / `+` / `.` での文字列の連結・引用符で囲まない `/` `-` `*` `<` で始まる値・
PostgreSQL のコマンド(`psql` / `createuser` / `pgbench` など)の `-P` は除きます)・Dockerfile の `ENV` / `ARG`(行末の `\` で続く行も)・
docker compose の `- POSTGRES_PASSWORD=...`(引用符で囲んだものも)・`docker run -e DB_PASSWORD=...` も同じです
(`.env` や compose の一覧の、引用符の外の行末の ` # コメント` は残します)。
キーの末尾の番号(`Password2`・`DB_PASSWORD_2`・`SMTP_PASS1`)は除いて判定します(小文字の `pass1` / `pass2` だけのキー
(`this.pass1` / `self.pass1` も)はコードの処理の段のことが多いため秘密系とみなしません)。区切りのないキー
(`DBPASSWORD`・`PGPASSWORD`・`sqlpwd`)も末尾の `password` などで判定します。
ODBC の `Pwd={...}` のように波括弧で囲んだ値も、閉じた波括弧の後が `;`・引用符・行末などなら `;` を含めて伏せます(それ以外は値の終わりまで伏せます)。書式の差し込みだけの値(`{0}`・`%s`・`${NAME}`。`${NAME:-既定値}` の既定値は伏せます)・
真偽値(`SavePassword` の `True` など)・表示の文言・キー名そのものの値(`SET_PASSWORD = "SetPassword"`)は伏せません。
`token` / `credentials` のようにコードでは別の意味でも使う語のキーは、値が秘密らしい(8 文字以上で、空白や `$` `#` `%` 括弧・
引用符などの記号を含まず、数字を含むか、大文字と小文字を含んで `NextToken` のような語をつないだ形でない)ときだけ
伏せます(字句解析の `token: "keyword"`・AWS SDK のページ送りの `"input_token": "NextToken"` などを伏せすぎないため)。ただし設定ファイル(appSettings・My.Settings)と、属性の形の
`token="..."`(コードの `token = "..."` も)は値によらず伏せます。
TypeScript / JavaScript・Java・C#・Go・Python のファイルは、言語の字句(文字列・コメント・数値とコードの区別)を読み、
上の規則で伏せる範囲のうち**文字列・コメント・数値の中の部分だけ**を伏せます(0.15.0 から)。`const apiKey = process.env.API_KEY;` の
`process.env.API_KEY` のようなコード(変数名・関数の呼び出し)は秘密の値ではないので伏せません(AI がコードを読めなくなるのを避けるため)。
字句を読み違えるおそれのある行(1 行で閉じるはずの文字列が閉じていない行)は行全体を文字列とみなし、字句の範囲と伏せる範囲を
対応づけられないファイルは、言語を区別しない伏せ方の結果をそのまま使います(どちらも伏せる側に倒す)。それ以外の言語・設定ファイルは
言語を区別せずに伏せます。
ランダムな英数字列(高エントロピー値)も既定で伏せます。置き換えた件数は実行時に表示され、
パックのヘッダーには AI 向けに伏せ字であることを明記します。まだ伏せない形もあります
(YAML の `password: ...` や INI の `db_password = ...` のような引用符のない値、C# の `DefaultSettingValue` 属性・複数行にわたる
文字列の連結、`String.Concat(...)`、VB の文字列や XML リテラルの中に書いた JSON / XML、
`serializeAs="Xml"` の設定値、PHP / Ruby の `'password' => '...'`、メソッドの引数の組(`props.put("password", "...")`)、
Dockerfile の空白で区切る古い形の `ENV DB_PASSWORD ...`、URL のパスワードの
エンコードしていない `;` の後ろ、コマンドの引数の値を `\"...\"` / `""...""` のようにエスケープした引用符で囲んだもの、
PowerShell の行の継続(`` ` ``)・`Invoke-Sqlcmd -Password`、`net.exe use`、`sqlcmd` の `/U` `/P` の形など)。

パックのほかに AI に貼る文面も、同じ規則で伏せます。

- `petari build` のエラーの文面(今のファイルの前後の行・エラーの本文・ログの末尾・ファイルとして読めないエラーの発生元)
- 適用に失敗したときのレポートの「実ファイルの該当箇所」の抜粋

抜粋はファイル全体を伏せてから切り出すので、複数行にまたがる値(行継続の代入・複数行の属性値・
秘密鍵)も伏せたうえで、行番号は実際のファイルと一致します。伏せ方はパックと同じで、`.vb` は
VB のソースとして、追加ディレクトリ(extraRoots)からパックに集めるファイルは言語を区別しない伏せ方でも
伏せます(適用のときはパックの構成を知らないため、`.vb` は両方の伏せ方で伏せます)。言語の字句を読んで伏せる
ファイルも、抜粋では言語を区別しない伏せ方の範囲まで含めて伏せます(伏せる範囲は広い方に揃える)。
高エントロピー値を伏せる設定(既定)では、伏せない設定で伏せる値も合わせて伏せます。
ビルドのエラーの本文が抜粋で伏せた値やその一部を引用しているとき(引用符を忘れた値が識別子として
報告されるなど)は、本文の引用も伏せます。伏せるのは抜粋で伏せた値そのもの(3 文字以上)と、その中の
3 文字以上の語(識別子らしい語(英字と数字の両方を含む・小文字の後に大文字が続く)はどこでも、それ以外の語は本文の引用の中だけ)です。載せる抜粋にひとまとまり(空白・引用符・括弧などで区切られた形)で見えている値・語は
伏せません(抜粋で AI に見えているため)。値の一部の 1〜2 文字の語や記号だけを引用した部分は伏せません。
あわせて本文そのものも VB のソースとして伏せ、シグネチャの省略可能な引数の文字列の既定値
(`[key As String = "..."]`)は名前に関わらず伏せます(コンパイラーはエラーのないファイルの宣言も
引用し、定数を参照する既定値は値に置き換えて引用するため)。

AI の回答に `[MASKED]` が残っていても、petari は伏せた後の内容で照合します。書き込むときに
元の値へ戻すのは、伏せ字を含む行を**一字も変えずに残した**行だけです(インデントの違いは除く)。
伏せ字を含む行を書き換えた・新しく足した・新規ファイルやコメントに書いた `[MASKED]` は、
値の取り違えや別の場所への書き出しを避けるため、書き込まずに止めます(その行は利用者が直します)。
伏せ字を含む行を元より多く書く回答も止めます(My.Settings の `<value>[MASKED]</value>` や設定のセクション・
分岐を写して足すと、別のキー・別の場所に同じ値が入るため)。伏せ字を含む行を書く変更のどれかが書かれないとき
(戻せない・当てる場所が見つからない・適用済みと判定した)は、`--partial` でも、同じ回答の中で伏せていた値を
消す変更(伏せ字の行を別のブロック・別のファイルへ移す回答の移動元など)を書きません。
伏せ字がそのままファイルに入って実際の値が消えることも、別の値が入ることもありません。
`[MASKED]` という文字そのものを書く変更(伏せる処理の実装など)は、利用者が
`--literal-masked` を付けたときだけ書き込みます。変更する範囲に実際の値を伏せた行があるときは、
付けても使いません(実際の値を `[MASKED]` の文字で上書きしないため)。

これは名前と形からの推定であり、すべての秘密情報を見つけられる保証はありません。
秘密情報をソースに書かない運用は引き続き必要です。無効化オプション(`--no-mask`)は
ありますが、既定は有効です。

### 4.3 クリップボード

`petari pack` は実行の最後に、チャットに貼るもの(パック全体、または大きいときは指示文だけ)を
クリップボードに入れます。`petari build` は失敗したときのエラーの文面を、適用に失敗したときは
失敗レポートを入れます。Windows の**クリップボードの履歴**や**デバイス間の同期**が
有効だと、その内容が履歴に残る・同期されることがあります。

- グループ ポリシー(コンピューターの構成 > 管理用テンプレート > システム > OS ポリシー)の
  クリップボードの履歴(Allow Clipboard History)と、デバイス間のクリップボードの同期
  (Allow Clipboard synchronization across devices)で無効にできます
- ツール側では `npx petari pack --no-clip` / `npx petari build --no-clip` と、`.petari/config.json` の
  `"clipReportOnFailure": false` でクリップボードを使わない運用にできます
  (この場合は出力ファイル・標準出力からコピーします)

### 4.4 チャット AI 側でのデータの扱い

送信したデータがチャット AI のサービス内でどう扱われるか(保存・学習への利用の有無など)は、
そのサービスの契約と設定(例: Microsoft 365 Copilot Chat のエンタープライズ データ保護)に
よります。petari の範囲外です。社内で承認済みのサービスとアカウントで使ってください。

### 4.5 DB の確認・動作検証(別ツール ashiato を使う場合)

petari は DB に接続しません。テスト用 DB の値を AI に確かめさせる運用
(運用ガイド 3-8・3-9)では、別ツールの ashiato(<https://github.com/ishibashi0112/ashiato>)が
次を行います。導入する場合は ashiato も審査の対象にしてください。

- `ashiato schema`: DB のカタログからテーブル定義を読み、`docs/db/schema.md` に書く(行の値は読まない)
- `ashiato query`: AI が書いた `.sql` を実行し、結果を Markdown でクリップボードに入れる。
  実行するのは SELECT / WITH だけで、書き込み・ロック・外部参照の語(INSERT、UPDATE、
  SELECT ... INTO、FOR UPDATE、EXEC など)が 1 文でもあれば 1 文も実行しない。さらに
  読み取り専用トランザクション(SQL Server は必ずロールバックするトランザクション)の中で実行する
- `ashiato verify`: AI が書いた手順ファイル(`.verify.md`)の手順を 1 つずつ表示し、人が操作して
  Enter を押すたびに、テーブルを読んで変化を期待と照合する。照合の結果(OK / NG、違い、変わった行)を
  Markdown でクリップボードに入れる。DB へは読み取り(SELECT)だけで、手順ファイルの内容を実行する
  ことはない(書かれているのは期待する変化で、SQL ではない)。`--save-session` を付けたときだけ、
  変化を `.ashiato/sessions/` に保存する
- 接続には SELECT だけを許可したユーザーを使う(ツール側の検査は一次の防御で、最後の防御ではない)
- 結果には DB の値が入る。チャットに貼ると送信されるため、本番ではなくテスト用 DB に限り、
  値を貼ってよいかを社内の決まりで決める

## 5. AI の回答を反映するときの安全弁

petari は changes.md の内容を**実行しません**。テキストとして解析し、ファイルの書き換えにだけ使います。

- **形式の検証**: 規約の形式に合わないものは何も書き込まずにエラーにする
- **全部か無しか**: 変更のうち 1 か所でも当てられなければ、何も書き込まない
- **パスの制限**: 絶対パス・`..`・UNC パス・ドライブ文字・`~`・代替データストリーム(`:`)・
  Windows の予約デバイス名を拒否する。シンボリックリンク経由でプロジェクトの外を指す
  書き込みも拒否する
- **履歴と巻き戻し**: 書き換え前後の内容を `.petari/history/` に保存し、`petari undo` で戻せる
- **二重適用の防止**: 同じ changes.md をもう一度当てようとすると止まる
- **文字コードの保全**: Shift_JIS / UTF-8 / 改行コードを元のまま保ち、変更していない行のバイト列は変えない
- **端末出力の無害化**: AI 由来の文字列に含まれる制御文字・双方向制御文字を取り除いてから表示する
- **伏せ字の扱い**: 失敗レポートの抜粋は認証情報を伏せてから載せる。回答の `[MASKED]` は、一字も変えずに残した行だけ元の値に戻して書き、それ以外は止める(§4.2)

`petari watch` は、ダウンロードされた changes.md を確認なしで当てる常駐モードです。
上の検証はすべて同じように効きます。書き込みはプロジェクトのフォルダ内に限られ、
`petari undo` で戻せます。

**AI が書いたコードが PC 上で動くのは、利用者がビルド・テストを実行したとき**です
(`petari build` もビルドを実行します)。.vbproj のビルドイベントのように、プロジェクトの
定義に書かれた処理はビルドの時点で動くため、AI が .vbproj / .sln を変えたときは特に差分を確認してください。
そのため、ビルドの前に git diff で変更を確認する運用を前提にしています(運用ガイドの手順も
この順です)。

## 6. 起動する外部コマンド

外部コマンドは引数を配列で渡して起動し、シェル(cmd / sh)を通しません。
PowerShell に渡すパスは単一引用符でエスケープしています。

| コマンド | いつ | 目的 |
|---|---|---|
| `powershell`(Set-Clipboard)/ `pbcopy` / `xclip` | `petari pack` の最後、`petari build` の失敗時、適用の失敗時 | 貼るもの・エラーの文面・失敗レポートをクリップボードへ入れる(`--no-clip` と設定で止まる) |
| `powershell`(Get-Clipboard)/ `pbpaste` / `xclip` | `petari --clip` のときだけ | changes.md をクリップボードから読む |
| `git ls-files` | `petari pack` で、VB.NET 以外の構成に `extraRoots` を書いていないとき | パックに入れるファイルの一覧を得る(読み取りだけ) |
| `git status --porcelain` | 適用の前 | 未コミットの変更があれば警告する |
| `vswhere.exe` / `MSBuild.exe` | `petari build` のときだけ | Visual Studio に付属する MSBuild を探してビルドする(`--msbuild` で場所を指定できる) |
| `reg query` | 引数なしの `petari` / `petari watch` | ダウンロードフォルダの場所を調べる(OneDrive へのリダイレクト対応) |
| `code --diff` | `petari show` | VS Code で差分を開く(コマンド名か絶対パスのみ許可) |
| `Start-Process` / `open` / `xdg-open` | `petari show` で VS Code が無いとき | 差分レポートを既定のブラウザで開く |

PowerShell の実行が制限されている環境では、クリップボードへのコピーが警告付きで失敗します。
出力ファイルはそのまま使えるので、手でコピーする運用に戻せます。

## 7. PC に残るファイル

| ファイル | 内容 | 扱い |
|---|---|---|
| `repomix-output.xml` / `repomix-output.prompt.md` | パック(コードを含む)と指示文 | プロジェクト直下。`petari init` が `.gitignore` に追加する |
| `petari.config.json` / `docs/` | プロジェクトの設定と設計書などのひな型 | `petari init` が作る。git にコミットする前提 |
| `.petari/config.json` / `.petari/history/` | PC ごとの設定、書き換え前後のファイルと changes.md の原本 | プロジェクト直下。`petari init` が `.gitignore` に追加する。履歴の件数の上限は設定(`historyLimit`)で決められる |
| 一時ファイル | Windows でクリップボードへ渡すためのテキスト、`petari build` のエラーのログ | `%TEMP%` に作り、使い終わったらすぐ削除する |
| 一時ファイル | ブラウザ表示用の差分レポート(HTML) | `%TEMP%` に作り、次の `petari show` の実行時に 1 時間より古いものを削除する |

## 8. 依存パッケージとサプライチェーン

petari は**実行時依存がゼロ**です(Node.js の標準機能だけで動く)。他者のコードも同梱していません。
インストール時に実行されるスクリプト(preinstall / install / postinstall)もありません。
パッケージの中身は自前のビルド結果(`dist/`)だけです。

0.15.0 で、以前の slnmix が使っていた依存(fast-xml-parser とその依存 7 パッケージ、iconv-lite と safer-buffer、
ignore)を自前の実装と Node.js の標準機能に置き換えました。

| 以前の依存 | 置き換え先 | 確かめたこと |
|---|---|---|
| fast-xml-parser(.sln / .vbproj の XML 解析) | `src/pack/xmlReader.ts` | 正しい XML 2 万通りで以前と同じ結果 |
| iconv-lite(Shift_JIS の読み取り) | Node.js の `TextDecoder("shift_jis")`(適用と同じもの) | 普通の日本語のソースでは同じ結果(違うのは不正なバイト列・0xF9 の外字などだけ) |
| ignore(.gitignore の判定) | `src/pack/services/gitignoreMatcher.ts` | `git check-ignore` と 12 万通りで同じ結果 |

slnmix のパッケージ(0.23.0 から)は、引数をそのまま petari に渡すだけの互換パッケージで、依存は petari だけです。
新しく導入する場合は petari だけを入れてください。

`npx` で都度取得すると、その時点の最新版になります。審査した版で固定したい場合は、次のいずれかを推奨します。

- 社内の npm レジストリ(ミラー)に審査済みの版だけを置き、そこから取得する
- `npm install -g petari@0.15.0` のように版数を指定して導入し、更新は審査の上で行う
- ソースを取得して `pnpm install --frozen-lockfile` でロックファイルどおりに入れ、
  ビルドしたものを配布する(ロックファイルに入っているのは開発用の依存だけです)

公開パッケージの中身は `npm pack petari@0.15.0` で取得して確認できます。

## 9. Claude Code / Codex などのエージェント型ツールとの違い

| 観点 | エージェント型ツール | petari |
|---|---|---|
| コードの送り先 | ツールの提供元の API(新しい送り先の審査が必要) | 社内で承認済みのチャット AI(既存の送り先のまま) |
| AI の実行権限 | PC 上でコマンドの実行・ファイルの編集ができる(許可の仕組みはある) | なし。AI はテキストを返すだけ |
| 送る範囲を決めるのは | エージェントが必要に応じて読む | 利用者がパックを作って貼る(中身はファイルで確認できる) |
| 変更の反映 | エージェントが直接書き換える | petari が検証してから書き換え、履歴を残す |

## 10. 残るリスクと推奨する運用

| リスク | 対策 |
|---|---|
| AI が誤った・悪意のあるコードを書く | ビルド・テストの前に git diff で確認する。変更は `petari undo` と git で戻せる |
| AI が .vbproj / .sln のビルド定義(ビルドイベント等)を書き換え、ビルド時にコマンドが動く | .vbproj / .sln の差分は特に確認してからビルドする(petari 自身が .vbproj に足すのは新規ファイルの登録行だけ) |
| ソースや文書に紛れた指示で AI の回答が誘導される(プロンプトインジェクション) | 回答はファイルの変更としてしか反映されず、パスはプロジェクト内に限られる。上と同じく差分を確認する |
| 認証情報のマスク漏れ | マスクは推定のため、秘密情報をソースに置かない。機密度の高い案件ではパックの中身を確認してから送る(ビルドのエラーと失敗レポートの文面も同じ規則で伏せる。§4.2) |
| git の一覧から集めるとき、コミットしていない手元のファイル(`.gitignore` に書いていないもの)が入る | 入れたくないファイルは `.gitignore` か `.repomixignore` に書く。パックの `<directory_structure>` で入ったファイルを確かめられる(§4.1) |
| クリップボードの履歴・同期 | グループ ポリシーで無効にするか、`--no-clip` で運用する(§4.3) |
| チャット AI 側でのデータの扱い | 承認済みのサービス・アカウントでのみ使う(§4.4) |
| DB の確認・動作検証で DB の値がチャットに渡る(ashiato を使う場合) | テスト用 DB と SELECT だけのユーザーに限る。貼ってよい値の範囲を社内で決める(§4.5) |
| パッケージの更新による混入 | 版数の固定・社内レジストリでの配布(§8) |

## 11. 他のチャット AI で使う場合

ツール側は特定のチャットサービスに依存していません。次の条件を満たすサービスなら同じ流れで使えます。

- 長いテキストを本文に貼れる(`petari pack` は約 12 万文字を目安にしています)か、ファイルを添付できる
- 回答のテキストをファイルとしてダウンロードできる、またはコピーできる
  (コピーしたものは `petari --clip` でクリップボードから適用できます)

実際の動作を確かめているのは Microsoft 365 Copilot Chat です(添付ファイル内の指示が
無視される・空行が落ちるなどの癖に合わせた調整は、そのサービスでの実測に基づきます)。
